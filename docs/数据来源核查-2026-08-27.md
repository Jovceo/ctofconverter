### 由本次核查触发的站内修正

- `locales/en/body-temperature-chart-fever-guide.json`
  - 表格 `hypothermia` 行原为 **"<36.0 °C = Hypothermia"** → 拆成两行：`hypothermia` **<35.0 °C（急症）** 与 `lowTemp` **35.0–36.4 °C（偏低，需复测）**。理由：腋温在健康成人里的均值就是 35.97 °C，把 <36 °C 标成低温症会大量误判。
  - 测量方式表的腋温备注原写 **"0.5–1.0 °C lower"** —— 权威写法是 **0.3–0.6 °C（= 0.5–1.0 °F）**，即把 °F 区间误标成 °C，属单位串位。已改为偏移表述，并把无出处的"各部位正常范围"换成 Merck 的偏移口径（口温保留 StatPearls 的 36.5–37.5 °C）。
  - 直肠偏移由 "0.5 °C (0.9 °F)" 对齐 Merck 的 "0.6 °C (1.0 °F)"。
- `pages/body-temperature-chart-fever-guide.tsx`：交互评估里 35.0–35.9 °C 不再显示 "Hypothermia / Danger"，改为 "Below Normal / Warning"（infant 分支保持原有更严的 <36.0 °C 判定，因为新生儿本就按 <36.5 °C 处理）。
- **站内未改动、但已知与来源不完全一致**：成人/儿童页面上的四档（37.6–37.9 / 38.0–38.9 / 39.0–39.9 / 40.0–41.0）没有权威出处（NHS、Mayo、CDC 都不发这种分级）。数据集里只发布 StatPearls 有出处的分档（37.3 / 38.1 / 39.1 / 41），并注明"两套数字回答的是不同问题"。页面配图为静态 webp，重排分档会让图文冲突，故暂不动——这是**有意留下的差异**，不是遗漏。

## 4. 复查方法

```powershell
# 逐条重放第 2 节的抓取（200 HIT 才算通过；403 属预期）
$urls = @(
  @('https://www.nhs.uk/symptoms/fever-in-adults/','38C'),
  @('https://www.nhs.uk/conditions/hypothermia/','35C'),
  @('https://www.ncbi.nlm.nih.gov/books/NBK545239/','36.5'),
  @('https://www.ncbi.nlm.nih.gov/books/NBK554181/','36.0')
)
foreach ($u in $urls) {
  $r = Invoke-WebRequest -Uri $u[0] -UseBasicParsing -TimeoutSec 25
  "$($r.StatusCode) " + ($(if ($r.Content -match [regex]::Escape($u[1])) {'HIT'} else {'MISS'})) + " $($u[0])"
}
```

任何一行变成 MISS：先改数据、再改 `version`、再改 `updated`，然后 `npm run generate:datasets` 并重跑 `npm run build`。不要只改页面不改数据集（两边都从 `config/datasets/` 取，页面文案与数据不一致时以来源为准）。
