### 复核补记（同日 19:08，站长指出修复不完整）

- `formatLabel` else 分支残留 bug：`key.replace(/([A-Z])/g, ' $1')` 对连续大写无效，`WEATHER → W E A T H E R`。影响面比首版判断更大——六个 scene name 里 `BODY` / `WEATHER` / `WATER` / `OVEN` 均无 `_`，全部走错分支。
- 最终实现（`utils/temperatureContext.ts`）：先去 `[_ ]+`、再按 camelCase 边界 `([a-z])([A-Z])` 插空格（必须在大写归一之前），最后 `toLowerCase()` + `\b\w` 逐词首字母大写。实测全量输入：`WEATHER→Weather`、`BODY→Body`、`EXTREME_COLD→Extreme Cold`、`normalBodyTemp→Normal Body Temp`（与旧 camelCase 路径结果一致，无回归）、`undefined→Standard`；36 个输入碎字模式 0 命中。
- `utils/textSpinner.ts`：`getVariantIndex` 之后残留一段不可达的重复 `return`（同块写了两遍），已删。
- **关键发现**：`components/TemperaturePage.tsx:1048` 的 `{/* {renderGranularInsight()} */}` 自 2026-02-12（commit `0053ba2`）起被注释——「💡 Analysis: {label}」卡片根本不渲染，所以 `formatLabel` 的 label 输出目前无用户可见出口；碎字泄漏的唯一活路是 `getDescriptionForScene` → `granularContext.description` → 拼进 meta description（同日修复 2 已断）。因此本地页面搜不到碎字并不等于线上干净：`curl https://ctofconverter.com/0-c-to-f` 实测 meta 与 JSON-LD 仍为 `... 0°C is a significant w e a t h e r benchmark.`，需部署后才消失。
- 顺带修掉 og 兜底缺口：`TemperaturePage` 的 `ogDescription` 旧逻辑只看 `strategy.meta.ogDescription`，缺失即退回站级模板句，导致 /37-5-c-to-f、/36-c-to-f 等页 description 具体、og/twitter:description 却是全站通用句。现改为 `strategy.meta.ogDescription → customMetaDescription → customDescription → generateOGDescription`；实测 /37-5 与 /36 的 og 已变成本页描述且与 twitter 一致。
- 旧 `public/*.html` 静态页实测无碎字（`w e a t h e r|b o d y|o v e n` 0 命中），无需回填修补。
- 复核口径：不依赖记忆——从源码里抽出 `formatLabel` 实际文本 eval 后跑全量输入；渲染侧用 `next dev -p 3111`（避开站长其他项目的 3000）实测 6 页 `spacedRuns=0`。`tsc` 通过，lint 仍 0 error / 24 warning。

### 改动 2：重写 `scripts/generate-sitemap.js`

**问题**：`getSitemapPages()` 返回硬编码 3 个页面（`SITEMAP_PAGES = ['index', 'oven-temperature-conversion', 'oven-to-air-fryer']`），`getAllPages()` 函数定义了但从未被调用。sitemap.xml 只有 3 条 URL，60+ 个页面无法被 Google 发现。

**改动内容**：

1. 新增 `getTemperaturePages()` 函数，扫描 `pages/` 目录下以数字开头的 `.tsx` 文件
2. 重写 `getSitemapPages()`，合并 `getAllPages()` + `getTemperaturePages()`，精做页面排最前
3. 重写 `getPriority()`：首页 1.0 > 精做页面 0.9 > 工具页 0.8 > 整数温度页 0.6 > 小数温度页 0.4 > 其他 0.5
4. 移除多语言支持：删除 `LOCALES`、`NON_EN_EXCLUDED`、`SITEMAP_PAGES` 常量，删除 `toHreflang()`、`getAvailableLocales()`、`getPageRollupLastMod()` 函数
5. 生成循环只输出英语 URL，移除 hreflang 标签和 `xmlns:xhtml` 命名空间
6. 从 `config/quality-pages.json` 读取精做页面列表
7. 排序：首页最前 -> 精做页面 -> 其余按自然顺序

**结果**：sitemap.xml 从 3 条 URL 变为 61 条英语 URL

### 改动 3：更新 `public/robots.txt`

**改动**：`Allow: /_next/static/` -> `Disallow: /_next/static/chunks/` + `Allow: /`

**理由**：GSC 抓取记录显示两周内 Google 抓取了 40+ 个不同 JS chunk 文件，纯浪费抓取预算。保留 `/_next/static/css/` 和 `/_next/static/media/` 的抓取权限。

**改动前**：
```

Allow: /_next/static/
Disallow: /_next/data/
Disallow: /_next/server/
Disallow: /_next/cache/
Disallow: /api/
Disallow: /_vercel/
```

**改动后**：
```
User-agent: *
Disallow: /_next/static/chunks/
Disallow: /_next/data/
Disallow: /_next/server/
Disallow: /_next/cache/
Disallow: /api/
```
