## 全局红线（新增 2 条，共 6 条，任何时候不可违反）

1. **迁移顺序红线**：新 Next.js 页面上线并验证 200 之后，才能把旧 `.html` 加入 `migrated-routes.json` 做 301。**绝不做指向 404 的 301**——当前 `/175-c-to-f.html` 是 200 而 `/175-c-to-f` 是 404（已实测），在新页就绪前动 301 等于亲手删掉高曝光页。
2. **单 URL 原则**：任何主题同一时间只允许一个正式 URL 在线（.html 或无后缀二选一），不允许双版本并行、canonical 打架。
3. 不升级 Next.js/React 大版本。**防御性冻结**：2026-01-23 的大版本升级与 Bing 崩塌时间精确吻合，但归因是时间相关性假设（待 T3/Bing 后台证据确认）；无论归因是否成立，恢复期不做全站级变更的成本为零。
4. 不批量新增多语言页面/JSON。**防御性冻结**：2026-04-22 批量上线与 4-26 Google 除名时间吻合；T1 已确认**无人工处置**、T2 显示 Google 于 4-24 抓取最后一轮后撤走抓取预算，归因收窄为「多语言批量上线触发算法性整站质量降级」（高置信，待恢复期观察最终定案）。无论定案如何，恢复期不做批量上线的成本为零。
5. 不改任何已收录 URL；构建产物（.next/cache 等）不入库。
6. Auto Ads 永久关闭；广告位规则见战略文档 §5。

## 风险预案（触发即停）

| 信号 | 动作 |
|---|---|
| Bing/GSC 展示连续 3 天为 0（原本非零） | 触发除名调查：URL Inspection + Messages + 近期部署 diff，48 小时内出结论 |
| Bing 点击连续 2 周 > 30% 下滑 | 暂停新页上线，检查最近部署与抓取错误 |
| GSC 出现手动操作通知 | 全线暂停内容生产，先按通知整改申诉 |
| 任何 301 指向 404 / 新页 5xx | 立即回滚该页 301（红线 1） |
| GA4 移动端跳出率 > 85%（有广告后） | 立即撤广告位 |
| Vercel 部署失败 > 24 小时 | 优先回滚恢复可用性（上次 Bing 崩塌与站点可用性直接相关） |
| 任何"批量"诱惑（批量生成/翻译/改 URL/改框架） | 直接拒绝 |
| **IndexNow 全量推送风险（v2.2）** | postbuild 每次部署都向 IndexNow 全量提交 63 URL——T7a 诊断期间**暂停部署**（不 push 即不触发）；诊断后改为仅推变更 URL 或降频 |
